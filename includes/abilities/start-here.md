# Bricks: start here

Use Bricks abilities as the connected site's source of truth. Ability names use slashes (`bricks/get-design-context`); direct MCP tools use hyphens (`bricks-get-design-context`). High-frequency abilities appear directly in `tools/list`; call other enabled abilities through `mcp-adapter-execute-ability` with `ability_name` and `parameters`. Use dispatcher ability `bricks/list-ability-status` only to distinguish dispatcher-only from disabled abilities.

## Fast workflow

1. For an exact page/component text replacement, unstyled page text insertion, safe component label/custom-attribute change, global-variable value replacement, or global-class/theme-style leaf edit supported by the live schema, call `bricks-commit-exact-site-edits` first. It accepts exact unique page/component/resource names and exact unique current element text or labels, so do not discover IDs first when those semantic selectors are available. For other known existing pages, templates, classes, variables, theme styles, or components, use the self-contained canonical fast path: call `bricks-resolve-agent-file`, edit the returned canonical file, then call `bricks-commit-agent-file` with the complete file (including its unchanged opaque baseline) and one stable idempotency key. Its default compact response is authoritative; request `responseFormat=document` only when the complete canonical file is needed for another edit. Do not add version, context, manifest, or generic discovery calls before an exact-target workflow.
2. For other workflows, execute dispatcher ability `bricks/get-mcp-version` once per session.
3. For a new homepage plus a brand/design-system brief on a fresh install, call `bricks-commit-site-foundation` first with one palette, header/footer interior HTML/CSS, and sibling homepage sections. It creates and verifies the real palette variables, fluid spacing and typography scales, root theme style, globally conditioned templates, homepage, and reading settings as one resumable same-key saga. It refuses a saved design foundation instead of overwriting it. For all other broad design-system writes, call `bricks-get-design-context` with `responseFormat: "summary"`; reuse existing tokens, classes, components, and breakpoints.
4. Load the task-specific skill before writing when skills are installed. For a new visual page, section, or template shell, load **bricks-html-css-to-bricks**. For broad discovery, begin with `bricks-checkout-site-repository`. For a precise page/component text replacement, unstyled page sibling insertion, safe component label/custom-attribute change, global-variable value, or global-class/theme-style leaf edit, use `bricks-commit-exact-site-edits` in one call; pages, components, and design resources accept an exact ID or exact unique name, and elements accept an ID or exact unique current text or label. Guard each operation with `expectedValue`; use literal `allowBlindWrite: true` only when the user intentionally supplied that exact target and requested replacement regardless of its current value. When target discovery or a fresh visible selection is needed, use `bricks-checkout-site-edit-map`, then `bricks-commit-site-edit-plan` with one stable idempotency key. Repeat the same commit call to resume or replay safely. Execute dispatcher ability `bricks/preview-site-edit-plan` only when an explicit dry run is required. Do not use typed routes for unadvertised operations or component property-controlled content. For other 2-25 target refactors, execute dispatcher ability `bricks/checkout-site-changeset`, edit its canonical documents, then execute `bricks/preview-site-changeset` and its apply/resume abilities through the same dispatcher. Changesets run pages first, refresh each design CAS just in time, checkpoint every inner write, and return canonical readbacks. They are ordered resumable sagas, never one atomic site transaction: stop on `partial_commit` or `manual_recovery` and inspect per-step evidence before another write.
   For a complete new static visual shell on a known empty page or template, author semantic HTML/CSS and make `bricks-commit-html-css-page-import` the first Bricks operation. This is a **page-body compiler**, not a whole-site bootstrap: omit `<main>`, and create site-wide header/footer content as Bricks templates instead of embedding those landmarks in the page. Send the complete body source, `documentPurpose: "page-content"`, `replaceExisting: false`, native-only policies when required, and one stable idempotency key. Page-content imports default `preserve_html_defaults` to false; set it true only when the source demonstrably relies on browser defaults. The facade captures current authority and commits generated variables, classes, and the page tree through the same journaled preview/apply pipeline. A warning-bearing candidate stops with a frozen token: review the compact `plan`, `render`, and `diagnostics.warnings`, then call `bricks-apply-html-css-page-import` with that exact token, the same idempotency key, and `acknowledgeWarnings: true` only after the warnings are accepted. For a non-empty explicitly owned external migration or a deliberate dry run, execute dispatcher abilities `bricks/get-page-elements` and `bricks/preview-html-css-page-import` to read `documentDigest`, preview once with `documentPurpose: "migration"`, that digest, and current design context version, set `replaceExisting: true`, and apply the frozen token after review. Before commit or preview, scope or remove document-level selectors that Bricks already owns and make relied-on browser defaults explicit—especially heading and paragraph margins, heading size/weight/line-height, and list spacing—because the Bricks reset intentionally replaces user-agent defaults. Execute dispatcher ability `bricks/convert-html-css-to-bricks-data` only when you need to inspect or modify the raw candidate before deciding how to persist it. For an external source migration, compare source and target computed root font sizes first; when they differ, pass `source_root_font_size_px` and `target_root_font_size_px` together so rem-based geometry keeps its rendered scale. Preserve computed content-root size/line-height, and keep `var(--font-*)` families in scoped CSS rather than native Bricks typography.
   For an existing canonical page, dispatcher ability `bricks/checkout-page-workspace` returns a lossless editable full-tree file only when the caller can access every executable payload in that tree. Pages containing Code/SVG source, query PHP, `{echo:...}` tags, or signed payloads fail closed without execute-code permission; a redacted element read must never be repackaged as an editable workspace. Preview and apply recheck the permission, so a token cannot survive permission revocation.
5. If conversion returns `code_sensitive_write_blocked: true`, do not persist any conversion-derived resources. Remove or replace every listed code-sensitive element, then rerun conversion and render validation.
   In CSS-only mode with `postId`, `elements_to_update` contains class-setting patches only, never complete saved settings. The converter still scans every matched authoritative element for Code/SVG source, query PHP, `{echo:...}` tags, and signatures; a blocked result does not authorize applying its class or design-resource suggestions.
6. When removing a source document wrapper, transfer its page-level typography and containment as well as descendant resets. Preserve `overflow: hidden|clip` when negative or viewport-relative pseudo-elements depend on it.
7. Before a raw global-variable write, execute dispatcher ability `bricks/list-global-variables` and pass its exact `variableOwnership` and `categoryOwnership` to `bricks/set-global-variables`; preserve returned opaque fields when replacing category rows through dispatcher-only `bricks/set-global-variable-categories`. Delete only with a variable row's ready `itemOwnership`. If `skipped_global_variables` is non-empty, compare every source value with the existing same-name variable and abort on any mismatch; the transactional import preview does this automatically. `bricks/generate-scale-variables` is preview-only until its variable and category changes can commit atomically: treat `save: true` rejection as a safety boundary, not permission to perform two unguarded writes.
8. When using the raw converter route, execute dispatcher ability `bricks/list-global-classes` immediately before persistence and pass its exact `ownership` as `expectedOwnership` to one `bricks/batch-create-global-classes` call through the dispatcher. If any class has a category, also pass `categoryOwnership` from that same read. Preserve converter IDs; do not remap or create classes one by one.
9. Save the unchanged converted tree and capture `revisionId` when returned.
10. Verify a broad element write once through dispatcher ability `bricks/get-page-elements` with `responseFormat: "summary"`. For token-bound imports, require its `documentDigest` to equal apply's `savedDocumentDigest`. Require `customCssOwnSelectorMismatchIds` to be empty: an element with `_cssId` must target that custom ID, not its absent default `#brxe-{elementId}` selector. Request detailed settings only for an affected ID when the summary or frontend exposes a mismatch.
11. With a browser, visually inspect desktop and 390px mobile. Without one, execute dispatcher ability `bricks/render-elements` with only `postId` and `responseFormat: "summary"`; do not discover the full ability catalog or resend the tree. A render summary cannot prove source root-scale, effective body-font parity, H1 display typography, or horizontal containment.

## Native page structure

For ordinary post/page content, omit `<main>` because the theme owns the document landmark. Use sibling sections:

```html
<section>
  <div class="brxe-container">
    <div class="brxe-block">...</div>
  </div>
</section>
```

Use Section for a full-width region, a direct Container for its constrained content boundary, Block for reusable inner layout groups, and Div only for semantic micro-wrappers. Stack multi-column hero/card rows at the mobile breakpoint. Keep primary mobile content in normal flow: no absolute positioning, negative margins, or translations. Give flexible children `min-width: 0`, `width: 100%`, and `max-width: 100%` where needed.

For a semantic full-width root, author the native hint on that element itself: `<header class="brxe-section">` or `<footer class="brxe-section">`, each with a direct `brxe-container`. If a source landmark already owns a site-width class such as `.container`, split it before conversion: keep the landmark as a full-width, spacing-neutral Section and move the width class, every source grid/flex/spacing class, and the original children to its direct Container. The outer Section may keep only classes that intentionally paint a full-width background or border. A Section with one direct Container must not retain the source grid/flex columns; require `singleContainerSectionLayoutRootIds` to be empty in the saved summary. Leave semantic cards as ordinary `<article>` elements; the converter preserves `tag: article` on a neutral Div. Add `brxe-block` only when the source truly needs Block's full-width flex-column behavior. Do not wrap these in another Section/Block and create duplicate layout primitives.

## Safety and integrity

- Never force duplicate resource names. Read the existing class, variable, color, or component and choose update, rename, or abort.
- Do not guess unfamiliar element settings, dynamic tags, conditions, interactions, forms, or queries. Read the matching runtime schema/ability first.
- When reading an element schema, pass only the `controlKeys` you plan to write. Full schemas for complex elements such as Form are large.
- Flat Bricks element IDs and references are exactly six characters. Nested `{name, children}` input may omit IDs for generation.
- Destructive abilities need explicit user sign-off and a readback/restore plan. Post element writes have revisions; global design resources do not.
- Parse structured ability error codes/data. Do not blindly retry a conflict, lock, disabled ability, or version-precondition failure.
- A write response alone is not proof. Confirm revision/readback integrity and the rendered result.

Reject horizontal overflow, clipped or overlapping content, unreadable type, placeholder links, duplicate/missing main landmarks, broken heading order, unnamed controls, or Builder/frontend disagreement. In source migrations, compare computed root and content-root size/line-height, effective body and heading families, responsive column counts, page/container/hero geometry, and key geometry. A literal computed `"var(--font-…)"` family or an H1 that falls back to inherited page-root typography is a hard failure: preserve explicit display typography in scoped CSS. If source base typography loses to the theme, apply its family, size, and line height through a reusable page-root class or scoped page setting. Confirm repeated bars/cards/media have non-zero painted dimensions; for data-URI images also require successful decode and non-zero intrinsic dimensions. Server-render validity cannot prove visibility or horizontal containment.
